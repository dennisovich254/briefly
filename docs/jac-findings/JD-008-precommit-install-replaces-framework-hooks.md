# JD-008: `jac precommit --install` replaces pre-commit framework hooks, which the guide calls a migration

- **Version:** jaclang 0.39.0, Ubuntu 26.04, x86-64, both profiles
- **Found:** 2026-11-04, phase 0 / 0.5 pre-commit hooks
- **Category / severity:** Documentation gap or error / Minor
- **Capability:** Tooling (`jac check`, `jac fmt`, `jac browse`, editor support)
- **Status:** open
- **Related:** JD-006; upstream searched 2026-11-04: no matching issue
- **Cost:** 0.5 h; workaround: do not run `--install`; `jac precommit --verify` runs as a hook inside the pre-commit framework (no code)
- **Canary:** none (Briefly never runs `jac precommit --install`, so nothing depends on this behaviour; re-check by hand at each upgrade)

## Behaviour

`jac precommit --install` in a repository whose hooks were installed by the pre-commit framework prints `Replaced pre-commit framework hook (backup at '.git/hooks/pre-commit.bak')` and writes a hook that runs only `jac precommit --verify`. Every other hook in `.pre-commit-config.yaml` (secret scanning, file checks, commit-message format, pre-push gates) stops running. The commit-msg hook is replaced the same way. Its new version rejects any message with a `Co-authored-by:` line naming Claude, Anthropic, OpenAI, Copilot, an AI or a bot, which is a policy Jac applies to the projects that install it.

The command is also hidden from `jac --help`. The CLI reference marks it "Hidden from `jac --help` (still functional)", and `jac precommit --help` and the reference disagree on the default scope (staged files against the project root).

## Expected

The CLI reference (`jac guide reference/cli --section jac-precommit`): "a hook generated by the python pre-commit framework is migrated automatically". "Migrated" suggests the existing hooks keep running. They don't: the framework's hooks are discarded (kept only as `.bak`). The reference should say they are replaced, or the installer should add Jac's check to the framework's config instead.

## Repro

`~/jac-repros/JD-008/repo/`: `git init`, a `.pre-commit-config.yaml` with one local hook, `pre-commit install -t pre-commit -t commit-msg`, then `jac precommit --install`. `.git/hooks/pre-commit` becomes:

```sh
#!/bin/sh
# Installed by `jac precommit --install`
exec jac precommit --verify
```

## Analysis

A project following the guide's wording would lose its secret scanning without noticing. The AI co-author rule conflicts with this project's commits, which carry a `Co-Authored-By: Claude` trailer. That rule is a documented policy, not a defect, but it is a second reason Briefly cannot use the installed hooks.

## Workaround

Briefly keeps the pre-commit framework as the hook runner and calls Jac's gate from it: the `jac-precommit` hook runs `jac precommit --verify` on the staged `.jac` files. `.pre-commit-config.yaml` says not to run `--install`.

## Canary

None: Briefly does not use `--install`. Re-check by hand at each upgrade (§21.5).
